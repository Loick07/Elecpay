# Rapport M1 — Mise en ligne par ngrok

État au 26/11/2026, branche `m1`. Tout est intégré dans `main`, CI verte. **M1.1, M1.2 et M1.3 sont
faits. M1.4 l'est en grande partie**, mais il reste le tour complet sur l'itel : le paiement jusqu'au
reçu et le nouveau PDF ouvert sur le téléphone. L'itel n'était pas joignable au moment de ce rapport
(voir « Ce qui reste »).

## Ce qui est fait

### M1.1 — Seed sûr (backend, accord de Loick)
- `DEMO_SEED_PASSWORD`, une variable secrète jamais affichée.
- **En production** :
  - `DEMO_MODE=true` est obligatoire ;
  - le mot de passe est refusé s'il est vide, s'il vaut `Demo2026!` (même en minuscules ou entouré
    d'espaces), ou s'il est trop faible ;
  - un secret 2FA est tiré au hasard **pour chaque** admin et super admin, et affiché une seule fois.
- La commande refuse **avant** d'ouvrir la base.
- `daily_tick` est permis en production de démonstration seulement ; `reset_db` est toujours refusé.

### M1.2 — Configuration ngrok et guide
- `backend/deploy/ngrok.env.example`, sans secret :
  - `RECEIPT_VERIFY_URL` et `CORS_ORIGINS` sur `https://omnivore-pardon-sixth.ngrok-free.dev` ;
  - `TRUSTED_PROXIES=127.0.0.1/32,::1/128`.
- `backend/deploy/public.ps1` :
  - une base dédiée, `elecpay_public`, avec son propre utilisateur MySQL ;
  - des secrets tirés sur le PC, jamais affichés ;
  - un garde-fou testé : 8 refus, 1 acceptation, en CI aussi.
- Le guide pas à pas : `backend/docs/DEPLOIEMENT.md`, section 7.

### M1.3 — Mise en ligne (par Loick)

- `verifier` répond « ok », en local et par ngrok.
- Aucun secret n'est passé par la conversation ni par le dépôt.

### M1.4 — APK release contre l'API en HTTPS
- **APK livré**, signé avec la clé de Loick : `apk_check` OK, 16,0 Mo pour l'itel, avec l'adresse
  ngrok compilée et le HTTP en clair interdit. **Installé sur l'itel**, puis mis à jour sans perdre la
  session (même clé).
- **Sur l'itel, sans tunnel USB** (`adb reverse` vide), l'application passe par Internet puis ngrok :
  - l'écran de connexion s'affiche, sans « Configuration invalide » ;
  - après la connexion de Loick, l'**accueil d'Arnaud se charge depuis `elecpay_public`** : facture
    en retard, carte du mois, barres de consommation (captures de 04:02 et 04:36).
- **API publique, vérifiée depuis le PC** comme la voit l'application :
  - `/health` répond « ok », mode démo ; le certificat HTTPS est valide ;
  - une route protégée sans jeton répond **401** ;
  - la vérification publique d'un reçu répond (404 propre pour un code inconnu) ;
  - en-têtes de sécurité présents : HSTS, CSP, `X-Frame-Options: DENY`, `nosniff`,
    `Referrer-Policy`, `X-Request-ID` ;
  - CORS : le domaine ngrok est **accepté**, une origine étrangère est **refusée** ;
  - le HTTP en clair est **redirigé vers HTTPS** ;
  - un navigateur reçoit la page d'avertissement de ngrok ; l'application, non.

## Décisions prises en route

- Le serveur ngrok tourne en `APP_ENV=production`, pour garder tous les garde-fous. Le seed et
  `daily_tick` y sont donc permis **seulement** avec `DEMO_MODE=true` : c'est la recommandation de
  `PLAN.md`.
- La facture PDF reprend la **mise en page** d'E²C, pas son **identité** : un PDF à l'en-tête d'E²C,
  avec des données simulées, serait une fausse facture officielle.

## Points à surveiller

- L'API n'est joignable que si **le PC est allumé**, avec l'API, les tâches et ngrok lancés.
- Après chaque `git pull` qui touche `backend/`, il faut **relancer l'API** (`Ctrl+C`, puis
  `.\deploy\public.ps1 -Step api`).
- La recherche « reçu » de l'Assistance attend toujours ta décision (défaut de la maquette, rapport
  F10).
- Une sauvegarde de la base vide de mon essai traîne dans `backend\deploy\sauvegardes\` (ignorée par
  git) : tu peux la supprimer.
